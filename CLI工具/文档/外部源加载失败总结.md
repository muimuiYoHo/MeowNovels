# 外部源动态加载失败总结

## 目标
支持在 exe 旁边的 `源/` 目录放入源文件，运行时自动加载。

## 尝试方案与失败原因

### 方案1：动态 import()
```js
const 模块 = await import(pathToFileURL(临时路径).href);
```
**失败**：exe（pkg CJS 模式）报 `Invalid host defined options`。pkg 的 CJS 运行时对动态 ESM import 支持有问题。

### 方案2：require() 直接加载
```js
const 模块 = require(临时路径);
```
**失败**：项目 `package.json` 设了 `"type": "module"`，`.js` 文件被视为 ESM，`require()` 不接受 ESM：
```
require() of ES Module not supported
```

### 方案3：require() + .cjs 后缀
```js
const 临时路径 = 文件.replace(/\.js$/, ".cjs");
const 模块 = require(临时路径);
```
**失败**：dev 模式（`node src/gui.js`）下 ESM 环境没有 `require`：
```
require is not defined
```

### 方案4：import() + require() 双模式
```js
if (typeof require !== 'undefined') {
  模块 = require(临时路径);
} else {
  模块 = await import(pathToFileURL(临时路径).href);
}
```
**未尝试**：复杂度过高，且 exe 下 import() 仍有问题（方案1）。

### 方案5：globalThis.工具 + ESM→CJS 转换
外部源的 `import { ... } from "../工具/xxx.js"` 改写为 `const { ... } = globalThis.工具`，再用 require() 加载。
**exe 成功，dev 失败**：同方案3，dev 模式无 `require`。

### 方案6：静态导入 + bat 脚本辅助
源注册用静态 import，提供 bat 脚本对比文件自动添加。
**采用**：放弃运行时动态加载，改为构建时静态注册。

## 根本原因

| 环境 | import() | require() |
|------|----------|-----------|
| dev (ESM) | 可用 | 不可用 |
| exe (CJS/pkg) | 不可用 | 可用（仅 .cjs） |

两个环境的模块系统互斥，无法用同一套代码同时支持动态加载。

## 最终方案
- `源注册.js` 静态导入所有源
- `更新源.bat` 扫描 `src/源/` 自动更新 `源注册.js`
- exe 不包含 bat 脚本

## 代价
新增源需要手动运行一次 bat 脚本，而非放入即用。
