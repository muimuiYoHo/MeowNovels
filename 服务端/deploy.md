# 喵小说服务端部署说明

服务端 = 喵番轻小说资源后端（查询 / 收集 / 格式处理 / 入库 / 更新 / 分发），
跑在 Docker 里，nginx 做反向代理，资源库存放于 E 盘。

## 目录结构

```
D:\Mui服务喵\
├── docker-compose.yml      # 编排：novel-server（node）+ novel-nginx（网关）
├── .env                    # 资源库主机路径、对外端口（默认 3080）
├── 部署.bat                # 一键：启动 Docker Desktop → compose up → 健康检查
└── 喵小说\
    ├── nginx\nginx.conf    # 反向代理配置（代理到 novel-server:3000）
    ├── 服务端\             # Node 服务端代码（全部中文命名）
    │   ├── package.json
    │   ├── Dockerfile
    │   ├── src\            # 主.js / 配置.js / 索引.js / 工具.js / 格式处理.js / 查询.js / 收集.js / 处理.js / 分销.js
    │   └── 测试\冒烟测试.mjs   # 全流程冒烟测试（本地跑，自动重置测试库）
    ├── 部署说明.md
    └── 更新日志.md

E:\资源库\轻小说\           # 资源库（容器内挂载为 /资源库/轻小说）
├── 索引\  库.json / 开放资源.json / 待处理.json / 资源记录.json
├── 待处理\  新增资源落点（临时）
├── 待更新\  更新资源落点（临时）
├── 人工\    .mui 等异常资源（人工判断，不自动处理）
└── 资源\   全文\{名称}\{id}.txt、分卷\{名称}\{id}-{卷}.txt（只存 utf8 简体）
```

## 日常命令

```bash
# 构建并启动（改了代码后重跑本命令即可热更新镜像）
cd D:\Mui服务喵
docker compose up -d --build

# 查看状态 / 日志
docker compose ps
docker compose logs -f novel-server

# 停止 / 清理
docker compose down
```

对外入口：`http://localhost:3080`（经 nginx）。服务端容器内端口 3000。

## 安全边界（防扒库）

- **外部只能经 nginx**：`novel-server` 不映射宿主端口（compose 无 `ports`，仅内网声明 `3000/tcp`），宿主机上 3000 无监听，外部无法直连 Docker 服务
- **nginx 路径白名单**：仅放行 `/健康`、`/任务`、`/上传/`、`/下载`，其余一律 404 且不转发后端（防路径探测）
- **限速限流（当前不启用，保留手段）**：下载 `5r/s`、任务/上传 `10r/s` 的 `limit_req` 配置已注释保留在 `nginx.conf`，需要时取消注释即可生效；启用前请确认客户端频率不会误伤
- **隐藏版本**：`server_tokens off`，nginx 响应头不泄露版本号
- 上传最大 2048m 流式（`proxy_request_buffering off`），JSON 请求体限制 1m

## 接口约定（工具端对接用）

所有响应统一 `{ 成功, ... }`，出错返回 `{ 成功:false, 错误 }`。请求里的中文字段照用。

### 1. 查询资源 — POST /任务

```json
{
  "行为": "查询",
  "来源": "mm", "外部id": "114514",
  "卷": "0",                  // "0" = 全文；分卷填卷号
  "全文": false,
  "编码": "utf8",             // utf8 | gbk | big5
  "语言": "简",               // 简 | 繁
  "外部更新时间": "2026/8/7",
  "全文长度": "123456"
}
```

返回：
- `状态: "不存在"` → 走官方下载，完成后「新增」上传
- `状态: "最新"` → 附带 `下载.url`（GET /下载），直接后端下载
- `状态: "过时"` → 走官方下载，完成后「更新」上传
- `状态: "需人工"` → 上传 .mui 文件（行为=异常）交人工

过时判定：外部更新时间与全文长度**都**落后 = 过时；仅一项落后 = 需人工。

### 2. 报告 + 上传 — 先 POST /任务，再 POST /上传/{令牌}

```json
// POST /任务
{
  "行为": "新增" | "更新" | "异常",
  "来源": "mm", "外部id": "114514",
  "名称": "书名", "编码": "utf8",
  "全文": false, "卷": "1", "语言": "简",
  "外部更新时间": "2026/8/7", "全文长度": "123456",
  "sha256": "可选，服务器会核验"
}
```

返回 `{ 成功, 令牌, 上传地址: "/上传/{令牌}" }`，然后：

```
POST /上传/{令牌}?文件名=书名.txt
Content-Type: application/octet-stream     ← 原始字节流，不要用 multipart
```

- 仅接受 `.txt` / `.mui`，其他格式 415
- 落点：新增→`待处理/`，更新→`待更新/`，异常→`人工/`，文件名前加 8 位日期
- 新增/更新上传后**自动后台处理**：编码转 utf8（已是跳过）→ 繁体转简体（已是跳过）→ 入库/替换
- 上传 .mui 时不带资源信息（信息写在 .mui 文本里），行为=异常，仅供人工查看

### 3. 下载 — GET /下载

```
GET /下载?行为=下载&来源=mm&外部id=114514&卷=0&编码=gbk&语言=繁
```

返回转换后的 txt（utf8 直接给；gbk/big5/繁体按请求转换）。

### 4. 健康检查 — GET /健康

## 约定与坑

- **全文长度** = utf8 字节数（Buffer.length），工具端计算后上传需一致，否则过时判定会失真
- Mui轻小说id 按入库时间顺序分配；id 分配与索引写入都在文件锁内串行，并发安全
- 索引 JSON 手改时保持数组结构（4 空格缩进）；`待处理.json` / `资源记录.json` 可为空数组
- 资源文件命名：全文 `{id}.txt`，分卷 `{id}-{卷}.txt`（如 `21-3.txt`）；`本地位置` 存**相对路径**（`资源/全文/xxx/1.txt`），容器/本地通用
- 容器内时间与宿主一致（Docker Desktop 自动同步），无需额外配置
- 服务端代码改动 → `docker compose up -d --build` 重建即可
- 本地跑服务端（不 Docker）：`node src/主.js`，用环境变量 `资源库根路径`、`端口`、`监听地址` 指到测试库
- **本机 docker.io 直连不通**：Dockerfile 基础镜像用 `docker.1panel.live/library/...` 加速镜像；新镜像先用加速器 pull 再 `docker tag` 回原名（见 nginx:alpine 用法）
- **compose 变量名必须 ASCII**：`.env` 用 `RESOURCE_LIB_HOST` / `EXTERNAL_PORT`（中文变量名 compose 插值会报错）；.env 里路径用 `E:/资源库` 正斜杠（反斜杠会被当转义）
- **旧版库数据迁移**：旧工具写的 `库.json` 是非法 JSON（`本地位置` 用 Windows 路径且反斜杠未转义），需改写为转义后的相对路径；原文件备份为 `库.json.bak-旧格式`

## 首次部署

1. 装好 Docker Desktop + WSL2（已装），重启电脑
2. 双击 `D:\Mui服务喵\部署.bat`
3. 浏览器访问 `http://localhost:3080/健康` 看到 `{成功:true}` 即完成
