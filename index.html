它是怎么做出来的？
真折射，不是毛玻璃

PDAim 的「苹果玻璃」不是 backdrop-filter: blur() 糊弄出来的。 它把页面内容重新画进一张纹理，再用 WebGL 做 SDF 圆角折射 + 色散 + 边缘高光。 下面把整条管线拆开，还能亲手拧参数喵~

WebGL1 SDF 圆角盒 RGB 色散采样 DOM → Canvas 快照 移动端降级
01

渲染管线

一帧里，玻璃是怎么「看见」背后内容的

1. 造背景纹理

开一张 2D Canvas，按 z 序把背景色、光斑、点阵、DOM 盒子、文字、图片重绘进去。文字甚至用 Range.getBoundingClientRect 逐字定位，保证和真实 DOM 对齐。

2. 喂给 WebGL

整屏共用一张 backgroundTexture；重叠的 header 再画一张局部纹理。另有 orbTexture（流动色斑）和 lineTexture（线条场）做气氛。

3. 片元着色器折射

每个 .liquid-glass-canvas 用 SDF 画出圆角形状，沿法线把采样点往中心「压」，形成边缘放大/扭曲；再按 RGB 偏移做色散，最后叠镜面高光和外缘阴影。

4. 性能闸门

DPR 上限 1.25（移动端 0.85）、最多 64 个玻璃输出、移动端 lite 模式直接关掉真玻璃、帧签名脏检查跳过无变化重绘。

02

着色器核心：五层效果

把 fragment shader 按贡献拆开，点开关看每层加了什么

A

SDF 圆角形状 sdRoundBox

圆角盒有向距离场给出「离边缘多远」和法线。可见性用 smoothstep 抗锯齿裁出形状，外侧直接 discard。

B

边缘折射位移 liquidRel

越靠边缘，折射因子 rel 越小，采样点沿法线向外偏移越多 → 产生「透镜边缘弯曲」。中心几乎不动，边缘弯得厉害。

C

RGB 色散 disp = 6.25

R / G / B 三个通道用略微不同的折射强度采样三次。玻璃边缘出现彩虹镶边——这是「真玻璃」和毛玻璃最容易看出来的差别。

D

镜面高光 + 内阴影 lightPos

相对光源方向用 cos(angle) 加权。朝光侧提亮，背光侧压暗；靠近边缘还有一圈细高光（num2 项）。

E

外缘厚度阴影 outer rim

SDF 外侧 6.25px 的环带按角度衰减压暗，模拟玻璃厚度投下的软影，让「浮起来」的感觉成立。

// 核心折射：沿法线把采样点拉向中心
// rel 越小（越靠边）→ (1-rel) 越大 → 位移越大
vec2 d = normal * distance;
vec2 g_coord = pixelCoord - d * (1.0 - ref);
// 色散：三通道错开采样
vec2 r_coord = pixelCoord - d * (1.0 - ref + dsp);
vec2 b_coord = pixelCoord - d * (1.0 - ref - dsp);

04

和 CSS 毛玻璃差在哪

为什么他们不直接写 backdrop-filter

CSS backdrop-filter

  • 只是把背后内容模糊，没有几何折射
  • 边缘不会「弯」，也没有真实色散
  • 高光 / 厚度感要靠多层 box-shadow 硬堆
  • 实现快、性能好、够用
毛玻璃字

WebGL Liquid Glass

  • SDF 法线位移 → 边缘真实透镜扭曲
  • RGB 三次采样 → 玻璃色散镶边
  • 光源角加权 → 镜面高光与内阴影一体
  • 代价：要重绘 DOM、吃 GPU、移动端要降级
真折射字

工程上值得抄的细节

  1. 画布污染兜底：跨域图会让 canvas tainted，上传纹理抛 SecurityError 就跳过不安全图重绘。
  2. 嵌套玻璃隔离：header 里的子按钮画局部纹理时，不能把父级玻璃自己画进去（shouldSkipUnderlyingElement）。
  3. 帧签名：滚动 / 主题 / 网格相位变了才重绘背景纹理，否则只刷输出。
  4. lite 模式：触屏或窄屏直接不跑真玻璃，避免手机烫手。
  5. 文字精确重绘：标题区用逐字 Range 对齐，价格 / 标签这类复合控件走 isCompositeTextElement 精确路径。
