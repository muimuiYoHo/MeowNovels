# 下载行为变化报告

let 测试对象 = 游戏王mxd;
```js
串行下载 → 分批并发 → 池并发
            踩坑
```

---

## 之前 - 串行

**行为**：逐个请求 顺序执行

```js
[请求1] → 等响应 → 解析 → 写入内存 → 等500ms → [请求2] → 等响应 → ...
```

**实测**（35%稳定后 ：
- 章速：0.3-0.5 章/s
- 效率：6-8 KB/s（原文），3-5 KB/s（简中）
- {测试对象} 预估：~30 min

---

## 分批并发（不要了

**行为**：合并 N 个请求为1批发出实现 N 并发

```js
{[请求1][请求2][请求3]} → 全部响应 → 全部写入内存 → 等500ms → {[请求4][请求5][请求6]}
```

**瓶颈**：本质仍是串行，批内最慢请求会拖累整批

**实测**（N=5 / 35%稳定后 ：
- 章速：2.2-2.4 章/s
- 效率：23-28 KB/s
- {测试对象} 预估：~5 min

---

## 现在 - 池并发

**行为**：指针给空闲工作者分配任务

```js
工作者A: [请求1]完成 → 等500ms → [请求4]完成 → 等500ms → [请求7]...
工作者B: [请求2]完成 → 等500ms → [请求5]完成 → 等500ms → [请求8]...
工作者C: [请求3]完成 → 等500ms → [请求6]完成 → 等500ms → [请求9]...
```

**实测**（N=5 / 35%稳定后 ：
- 章速：4.0 章/s
- 效率：47 KB/s
- {测试对象} 预估：~2.5 min

---

## 性能对比

| 模式 | 章速 章/s | 效率 KB/s | 耗时 | 相对串行提升 |
|------|------|------|-----------|----------|
| 串 | 0.3~0.5 | 6~8 | ~30 min | 1x |
| 批 | 2.2~2.4 | 23~28 | ~5 min | ~6x |
| 池 | 4.0 | 47 | ~2.5 min | ~12x |

## 架构变化

### 源请求

```js
源.下载() → 直接调 发送请求() / fetch() → 自己管进度/写入/吃错误
```

### 现在 - 框架调度

```js
源.下载() → 组装任务列表 → 调用 批量下载({ ... })
                              ↓
                        框架处理：并发池/请求/进度/写入/错误
                        源提供：URL/HTML 解析
```

**收益**：

- 没什么效率提升，只是源要自己处理的事情少了，这叫**优化底层代码**

---

## 超时

- 一般是网络问题导致的，没有改动只是提一下
- 默认 30 s判定死亡，超时后报错跳过，不影响其他并发但是会影响txt
- 错误类型：`network timeout`连接超时 / `Response timeout`响应超时 / `ECONNRESET`服务器断开
